状态：已实现并完成回归，尚未提交或发布。本文以 2026-10-12 确认的规则为准，实际验证记录见第 10 节。

## 1. 事件路径与基本约定

沿用 path + 参数路径，不新增独立 Params 字段。事件 Source 由组件实际挂载位置、CR 声明名称及本次调用参数组成。

```csharp
[Cfet2Status]
public double Temperature(int device, int channel)
{
    // 返回指定设备、通道的当前值。
    return ReadTemperature(device, channel);
}
```

若基础 CR 为 `/device/Temperature`，参数 device=1、channel=2 的事件 Source 为 `/device/Temperature/1/2`。

- 参数按 getter 声明顺序表示，补齐默认值；params 按元素顺序展开。
- SubscribeResource 的本地相对地址必须以 `/` 开头；缺少前导 `/` 的地址在初读前抛 ArgumentException，不执行 getter、不创建 Token 或观察句柄。已有完整 cfet URI 和远端 URI 入口保留。
- 订阅路径由开发人员明确指定并保证与实际发布 Source 一致。参数可为初读转换类型，但框架不补写、规范化或推断后续订阅地址；例如订阅 `/01` 不会自动改为 `/1`。
- 按已确认约定，参数不包含 `/`，不扩展 Get 的百分号编码或解码规则。
- 零元素 params 调用发布到基础 CR 路径。例如 `Values(params int[] channels)` 传入零个元素时 Source 为 `/device/Values`；若还有其他固定或默认参数，则这些参数仍保留在路径中。
- 不支持的参数表示、缺失必填参数及无法按 Get 规则还原的路径，应明确报告错误，不猜测参数。
- 发布比较基准按完整参数化路径分别保存，不同通道互不影响。

## 2. 三个订阅入口

以下表格描述已实现契约。本地入口的初读、自动观察及 WS 接入差异见后文。

| 接口 | 匹配方式 | 初读行为 | 自动观察 | 适用场景 |
|---|---|---|---|---|
| Subscribe | EventFilter，支持正则；字面精确条件需转义 | 不 Get，不返回初值 | 不启动 | 只接收主动事件，订阅精确参数、全部参数或参数前缀 |
| SubscribeResources | EventFilter，支持正则，组合事件订阅与合格资源观察 | 为新建的合格无参数观察读取初值；含参数资源不 Get | 仅合格无参数资源，复用共享观察 | 一次接收多个资源事件，同时自动观察合格无参数资源 |
| SubscribeResource | 一个精确资源及参数路径，不接受正则表达式作为匹配条件 | 必须 Get 一次并返回有效 InitialValue | 无参数资源按既有资格规则；含参数资源不启动 | 先读取具体资源当前值，再接收该精确来源的后续事件 |

SubscribeResources 的观察初读不作为 changed 事件发布，也不通过组合接口返回逐资源初值。共享已有观察时不因加入需求重读基准。Started/Shared/Skipped/Failed 是建立时观察结果，原始事件过滤范围独立保留。

普通 Subscribe 与 SubscribeResources 保留来源、事件类型配对 OR、完整匹配和忽略大小写规则。SubscribeResource 的“精确”指字面路径匹配，不意味着它跳过参数解析或要求该详细路径作为独立 CR 注册。

## 3. 参数路径的订阅范围

以基础 CR `/path` 为例：

| 条件 | 接收范围 |
|---|---|
| `/path`，字面精确条件 | 只接收 Source 为 `/path` 的事件，例如零元素 params 调用 |
| `/path/1/2`，字面精确条件 | 只接收这一具体参数组合 |
| `/path/.*`，正则条件 | 接收 `/path/` 后的全部子路径事件，不包含 `/path` 本身 |
| `/path/1/.*`，正则条件 | 接收参数前缀为 1 的后续子路径，不包含 `/path/1` 本身 |

`/path/1/.*` 不匹配 `/path/10/2`。如需精确 `/path/1`，单独登记字面精确条件；不扩大上述正则以隐式包含基础或前缀路径。

当资源声明恰好只有一个参数时，`/path/1/.*` 通常不会匹配辅助函数产生的完整路径，因为其后没有剩余参数。前缀订阅主要用于多参数或可变参数事件。

EventFilter 当前是正则接口。使用 Subscribe 或 SubscribeResources 精确接收路径时，须 Regex.Escape；否则路径中的点号等字符可能被当作正则。

```csharp
// 以下片段放在业务方法内，需引入 System.Text.RegularExpressions
// 以及 Jtext103.CFET2.Core.Event。

// 只接收通道 1/2，不初读、不观察。
var exactToken = MyHub.Subscribe(
    new EventFilter(Regex.Escape("/device/Temperature/1/2"), "changed"),
    e => Handle(e));

// 所有带参数子路径，不包含基础 CR 自身。
var allToken = MyHub.Subscribe(
    new EventFilter(Regex.Escape("/device/Temperature") + "/.*", "changed"),
    e => Handle(e));

// 设备 1 的后续参数子路径。
var prefixToken = MyHub.Subscribe(
    new EventFilter(Regex.Escape("/device/Temperature/1") + "/.*", "changed"),
    e => Handle(e));

// 使用完后释放自己的事件订阅。
exactToken.Dispose();
allToken.Dispose();
prefixToken.Dispose();
```

这些示例为本地过滤器写法。远端 Host 按现有通信配置单独设置，不应把经过 Regex.Escape 的完整远端 URL 当作 URL 输入解析。

## 4. 所有含参数 getter 必须主动发布

只要 getter 声明了参数，就不允许自动观察，不根据参数是否必填、本次是否传入参数来例外处理。

```csharp
Temperature(int channel)             // 不观察
Temperature(int channel = 7)         // 不观察
Temperature(params int[] channels)   // 不观察，包括零元素调用
```

索引 getter 同样不自动观察。普通 Get 仍可读取指定参数、使用默认参数或传入空 params；禁止的是自动轮询，不是读取或事件订阅。

统一规则适用于独立观察句柄、SubscribeResources、AutoObserveList、精确订阅的观察分支以及 WS；未来 MQTT 同样复用。含参数资源建立结果为 Skipped，并有明确原因，不调用 getter；原始事件过滤器仍保留。

对于无参数 getter，现有类型资格、Cfet2Event、AutoDenyList 和共享观察规则继续生效。AutoDenyList 只禁止观察，不禁止 SubscribeResource 的一次初读或组件主动事件。标记 Cfet2Event 的资源使用原生事件，不启动轮询。

组件在实际采样、更新等位置调用辅助函数：

```csharp
PublishResourceIfChanged(
    nameof(Temperature), value,
    parameters: new object[] { device, channel },
    timestamp: sampledAt);
```

首次有效值发布，后续内容变化才发布；只有 Core 接受入队后更新该完整路径的基准。源端时间戳保留。直接 Publish 沿用既有行为，组件自行保证 Source 含实际所需参数。不要求每次 Set 都发布。

## 5. SubscribeResources 的使用

```csharp
using var subscription = MyHub.SubscribeResources(
    new EventFilter("/device/.*", "changed"),
    e => Handle(e));
```

- 匹配本地已注册资源目录，为合格的无参数 Status/Config 建立或共享观察。
- 对所有含参数 getter 返回 Skipped，不初读、不枚举参数、不为通道建立观察。
- 事件过滤器仍匹配实际发布的详细路径，例如 `/device/Temperature/1/2`。
- `/device/Temperature/.*` 不匹配基础注册 CR，不要求先发现通道资源；即使观察集合为空，事件订阅仍有效。
- 单资源不支持或初读失败不阻止其他资源和原始事件接收；退订释放自身观察引用，不影响其他订阅或常驻需求。

## 6. SubscribeResource 的精确初值契约

调用方式：

```csharp
// 初读指定参数一次，然后只接收该完整路径的主动事件。
using var subscription = MyHub.SubscribeResource(
    "/device/Temperature/1/2",
    e => Handle(e));
var current = subscription.InitialValue;
```

执行流程：

1. 按精确地址定位基础 CR，解析实际调用参数；不把输入当作正则条件。
2. 按 getter 参数信息校验数量并转换类型，初读允许声明默认值及空 params；事件过滤使用调用者指定的路径，不生成替代订阅地址。
3. Get 一次取得有效初值。失败时拒绝订阅，不保留事件 Token 或观察句柄。
4. 登记完整路径的字面精确事件过滤器，不使用基础 CR 替代详细参数路径。
5. 含参数 getter 到此结束，不建立观察；无参数 getter 按现有规则建立或共享观察。

必填参数资源仅传基础 CR 时缺参失败，不自动降级为纯事件订阅。全部参数有默认值时，基础地址可按默认值初读，但后续只接收基础路径事件，不自动改成默认参数详细路径。要接收辅助函数发布的 `/7`，调用者必须明确订阅 `/7`。只有 params 且传入零个元素时，基础路径可精确初读并接收基础路径事件，仍不观察。

初值只通过 InitialValue 返回，不作为 changed 主动发布。SubscribeResource 与普通 Subscribe 的差别是需要有效初值，而不是所有精确事件订阅都需要 Get。

## 7. WS 与远端初读

- 普通 WS 事件订阅详细参数路径或正则时不初读、不观察；只转发匹配的主动事件。
- WS 来源条件精确命中基础注册 CR 时，含参数 getter 应走纯事件订阅分支，包含默认参数及零元素 params 情况，避免调用 SubscribeResource 造成额外初读或失败。
- 无参数基础资源保留现有 WS 精确初读及合格自动观察行为；正则组合依照第 5 节处理。
- 应用显式调用远端 SubscribeResource 时，由资源读取通信取得初值，再通过事件通信登记精确接收需求。该行为与普通 WS Subscribe 请求不同。
- WS 服务端不重复读取含参数资源，不增加 ACK 携带初值的协议。完整/精简载荷继续使用参数化 Source 并保留源端时间戳。

远端 SubscribeResource 保留完整 URI 初读流程，随后使用调用者提供的来源路径做字面精确匹配，Host 独立解析，不对完整 URL 先转义。不增加规范路径返回元数据，也不根据远端 getter 推断订阅地址。

## 9. 验收要求

- 所有含参数 getter 在各观察入口均跳过，不执行 getter；覆盖必填、默认参数和空/非空 params，更新以前允许默认参数观察的测试。
- Subscribe 精确字面、全部子路径、参数前缀匹配正确；点号等正则字符不会导致精确订阅误匹配。
- 零元素 params 事件由基础路径精确条件接收，子路径正则不接收；前缀与其子路径的边界同样验证。
- SubscribeResources 同时接收无参数自动事件与含参数主动事件；只为合格无参数资源建立观察，事件范围不因 Skipped 缩小。
- SubscribeResource 初读正确参数一次、返回有效 InitialValue、只接收指定完整路径且不轮询；覆盖别名、多参数、默认参数、params 和订阅地址不改写。
- 缺参、过多参数、错误类型、初读失败均不遗留订阅；初值不发布为 changed。
- WS 基础含参数 CR、详细路径和正则不初读；无参数行为及完整/精简载荷保持兼容。
- 远端初读与后续 Source 对齐，不重复初读；不同参数发布基准独立，时间戳保留。
- Core 与 WS 全量回归；实际结果见第 10 节。
