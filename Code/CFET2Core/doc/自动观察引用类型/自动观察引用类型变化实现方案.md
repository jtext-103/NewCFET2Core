# 自动观察引用类型变化实现方案

日期：2026-10-10

## 范围

在现有标量自动观察基础上，仅增加数组、List<T>、Dictionary<TKey, TValue>。不开放自定义对象、容器子类、接口声明、object、任意 IEnumerable 或集合 struct。容器元素和值递归支持原有标量和这三类容器；字典键仅支持原有标量。Status<T>/Config<T> 继续按 T 判断资格。原生事件、必填参数、黑名单、共享观察和固定目录规则不变。

## 内容比较

- 数组比较运行时类型、维数、各维长度及下界，再按位置递归比较元素，支持多维和锯齿数组。
- List 比较运行时类型、数量、顺序及元素。
- Dictionary 比较运行时类型、数量、键和值，忽略插入顺序；快照保留原字典键比较器，比较时双方均检查对应键和值，避免不同比较器导致方向不对称。
- 标量沿用 object.Equals，null 与非 null 不同；不比较时间戳和其他 Context 元数据。
- 不支持自定义对象及循环引用。声明类型先校验，读取时再校验实际值；快照失败不可当作有效变化。

## 独立快照与发布

首次有效读取时递归复制值作为比较基准，不发布初值。每轮有效读取捕获独立快照，内容相同不发布；内容变化后再复制一份作为事件值，避免订阅者修改事件值污染观察基准。事件值保留原容器类型。业务原对象在发布后继续变化，不影响事件值。

仅自动观察执行上述深复制，不改变开发者直接 Publish 的现有行为，不对整个 Context 做深复制。复用已有源端时间戳流程。Core 入队成功后才更新基准，入队成功不代表远端已收到；增加内部 TryPublish 返回是否接受入队，公共 Publish 签名不变。

初读快照失败报告 Failed，不建立观察。运行期读取或快照失败记录诊断并保持旧基准，下一轮继续尝试。自定义复制和比较不放在管理器全局锁内；每个资源读取门继续串行化该资源轮询。

组件仍负责 getter 返回值的一致性：观察锁不能阻止业务线程并发修改容器。业务侧应使用锁或返回一致副本；容器复制不能保证获得任意并发写入中的原子快照。

字典键比较器随快照保留，组件须保证其比较规则稳定。容器快照及比较开销随元素数量增长，每轮读取都会复制比较值；只在内容变化时再复制事件值。

## 组件示例

```csharp
[Cfet2Status]
public int[] Channels { get; } = new[] { 10, 20 };

[Cfet2Status]
public List<double> Temperatures { get; } = new List<double> { 10, 20 };

[Cfet2Config]
public Dictionary<string, int[]> Groups { get; set; }
    = new Dictionary<string, int[]> { ["A"] = new[] { 1, 2 } };
```

这些声明可从精确、正则或常驻列表入口建立观察，无需添加 Cfet2Event。内容原地变化可触发 changed，内容相同的新实例不会触发。示例仅展示声明，实际读写仍应按组件业务的并发模型同步。添加 Cfet2Event 后沿用原生事件规则，不建立自动观察。

Dictionary 的非 null 可空标量键也受支持，null 键仍遵循 Dictionary 本身的限制。数组支持 null 元素、空数组、多维数组和锯齿数组；List 和 Dictionary 的 null 值按内容比较。

## 修改位置

1. ResourceObservationTypePolicy：递归声明类型资格检查。
2. ObservationValueSnapshot：递归复制及内容比较，不依赖 JSON。
3. ResourceObservationManager：初读和轮询保存快照；发布值与基准分离；成功入队后更新基准。
4. EventHub：内部 TryPublish，保留公共 Publish 行为。
5. Core/WS 测试：调整旧数组拒绝用例为真正不支持类型，新增容器行为和传输测试。

## 验收

- 数组、List、Dictionary 的精确、正则及常驻观察复用统一流程。
- 同一容器原地修改能触发；相同内容的新实例不重复发布。
- 增删、顺序变化、嵌套元素、null、多维数组均按定义判断。
- 字典重排不发布；键或值变化发布；保留自定义键比较器。
- 比较基准与事件值不与业务对象或初读样本共享可变容器；SubscribeResource 返回初读样本的既有契约保持不变。
- 初读快照失败不持有句柄；轮询快照失败保留基准并能恢复。
- 原生事件与直接 Publish 行为保留；WS 正常传递容器值和源端时间戳。
- Core 与 WS 全量回归。

本阶段不增加 minDelta。后续阈值仅作用于数值标量，容器仍按整体内容变化判断。
