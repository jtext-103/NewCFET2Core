# 自动观察列表实现方案

日期：2026-10-09

AutoObserveList 为本地资源建立由应用持有的常驻观察需求；AutoDenyList 在 Core 的统一观察入口禁止自动轮询。两个列表复用已有资源匹配、观察资格检查和共享句柄，不创建额外的事件订阅。配置采用启动快照，修改后重启生效。

本文第 1 节列出列表的需求范围与行为边界。已有观察机制见 [Core 正则资源观察实现文档](../Core%20正则资源观察/Core%20正则资源观察实现文档.md)。

2026-10-10 后续扩展：数组、List、Dictionary 已纳入统一观察类型策略，常驻列表也可观察这些容器；自定义对象等仍跳过。详见 [自动观察引用类型变化实现方案](../自动观察引用类型/自动观察引用类型变化实现方案.md)。下文测试数量保留为本阶段历史记录。

## 1 范围和行为

| 命中情况 | 自动观察 | 事件行为 |
|---|---|---|
| 命中 AutoDenyList，包括同时命中两个列表 | 不获取观察句柄，不启动周期读取 | 普通订阅、主动发布和转发不受列表限制 |
| 仅命中 AutoObserveList | 组件启动完成后获取一个常驻观察句柄 | 变化通过已有发布链路产生 changed |
| 两个列表均未命中 | 保留现有按需观察；最后一个需求释放后停止 | 保留现有事件语义 |
| 两个列表为空 | 不增加常驻观察，也不禁止按需观察 | 保留现有事件语义 |

同一资源命中多条规则时，只持有一份列表观察引用。列表与本地、WS 以及独立句柄共享同一轮询。未来 MQTT 必须通过相同 Core 入口获取资源句柄。

观察资格仍限定为受支持的 Status 和 Config。原生事件、所有含参数 getter（含默认参数、params 和索引 getter）以及不支持的类型跳过。2026-10-12 起取消默认参数 getter 自动观察，普通 Get 和显式 SubscribeResource 初读仍可使用默认值。列表不能用于枚举参数通道。资源目录按初始化时快照处理，不提供运行中增删资源、重注册或列表重新扫描。

本阶段包含列表配置、启动与清理、诊断、Core 测试及 WS 回归。minDelta、参数化主动事件辅助函数、MQTT 传输和精确订阅缺参契约调整仍是独立工作项。

## 2 配置格式

GlobalConfig.json 使用以下格式；示例中的其他连接字段按实际部署填写。

```json
{
  "IP": "http://127.0.0.1",
  "Port": "8000",
  "Accept": "application/json",
  "AutoObserveList": [
    { "Path": "/device/Temperature" },
    { "Regex": "/sensors/.*/Value" }
  ],
  "AutoDenyList": [
    { "Path": "/sensors/debug/Value" }
  ]
}
```

每个条目必须且只能提供一个字符串字段 `Path` 或 `Regex`，字段名区分大小写。缺省列表、JSON null 和空数组都表示空列表。空条目、null 条目、未知字段、同时指定两个字段、空表达式及非法正则均报配置错误。

- `Path` 是本地注册资源的完整路径，按字面值匹配，忽略大小写。实现先转义正则元字符，因此路径中的点号不会变成通配符。
- `Path` 必须以 `/` 开始，不接受远程 URL、查询参数或片段。使用注册目录中的路径，不自动补齐组件名、修剪尾斜杠或解码路径。
- `Regex` 匹配本地资源路径，不接受包含 `://` 的远程地址表达式。沿用 EventFilter 的完整匹配、IgnoreCase 和每次正则匹配 100ms 超时语义；不额外改变现有正则锚点和分组行为。
- 列表内按 OR 匹配，两个列表可以合法重叠，禁止列表优先。
- 未匹配到资源的规则记录 Warn，便于发现拼写或部署路径错误。它不导致所有配置失败。

配置类 `ObservationListRule` 不可变；GlobalConfig 列表赋值会复制容器，调用方后续修改原数组不能改变配置。

### 2.1 兼容现有配置接口

`GlobalConfig.Populate` 读取 JSON 对象，接受原有标量字段及新增数组字段。`GlobalConfig.Get/Set(Dictionary<string,string>)` 签名保留，两个列表在字典中用 JSON 数组字符串表示。这样既可读取原生数组文件，也可读取由 Get 返回字典序列化得到的文件。

Populate 与 Set 共用列表解析和验证。在修改配置前，先校验两个列表和必要的 IP、Port、Accept 键。非法列表不会部分更新全局配置；旧文件缺少列表字段时恢复为空列表。

`GlobalConfig.Get()` 返回当前配置值，不代表配置已经写入磁盘，也不代表运行中的 Hub 已应用这些值。

## 3 启动快照和挂接时机

正常宿主的顺序为：

```text
GlobalConfig.Populate
  → 创建 HubMaster / EventHub，捕获并编译列表快照
  → 注册组件
  → StartCommunication
  → StartThings：启动 RootThing 和各业务组件
  → InitializeAutoObservations：匹配目录并获取常驻句柄
```

AutoDenyList 从 EventHub 创建起有效，覆盖通信已启动、组件尚未全部 Start 的窗口。AutoObserveList 在全部 Thing.Start 正常返回后初始化，使其初读可以访问已经启动的组件。

这只确定列表初始化的时机。普通本地和 WS 订阅仍可在资源注册后建立，不增加统一等待 Start 的机制。Thing.Start 抛异常时，列表初始化不会执行；不会把失败的启动当作完成。

列表只初始化一次。内部重复调用不会增加引用或重试失败资源。宿主现有 StartThings 本身仍不是可重复调用的重启接口。首版不提供手动刷新列表或重新初始化 API。

运行中修改 GlobalConfig 的列表仅影响下一个新建的 Core 实例。当前实例的 `Hub.ActiveObservationConfiguration` 返回不可变的生效快照，供诊断时与 GlobalConfig 中的配置值比较。正常部署通过重启应用应用新配置。

## 4 自动观察准入

`EventHub.AcquireResourceObservation` 在调用 ResourceObservationManager 之前检查 AutoDenyList，然后沿用现有资源资格检查。

| 情况 | 返回结果 | getter 和句柄 |
|---|---|---|
| 命中禁止列表 | Skipped，ReasonCode 为 DeniedByAutoDenyList | 不执行自动观察初读，不获取句柄 |
| 禁止列表匹配超时 | Failed，ReasonCode 为 ListMatchFailed | 不按未命中放行，不获取句柄 |
| 资源不合资格 | Skipped，保留现有原因说明 | 不执行自动观察初读 |
| 已有共享观察 | Shared | 增加独立句柄，不重新初读、不重置比较基准 |
| 可观察且初读成功 | Started | 建立首个观察句柄 |
| 初读无效或失败 | Failed | 不保留该资源的句柄 |

禁止列表只约束观察准入，不参与事件过滤，也不改变资源普通读写。正则组合保留原始事件过滤范围，命中禁止列表的主动事件仍可分发。

### 4.1 精确订阅适配

精确 SubscribeResource 保留现有资源类型、事件类型、观察类型及有效初值检查。对于符合原精确订阅契约的资源，即使命中禁止列表，仍读取并返回一次初值；随后登记事件订阅而不建立周期轮询。该初读是订阅返回的快照，不是常驻观察或重复轮询。

ObserveResource 原来对所有无句柄结果抛异常。本次仅对明确的 DeniedByAutoDenyList 原因保留订阅并记录 Warn，不将其他 Skipped/Failed 一律降级为事件订阅。黑名单中的必填参数资源经精确入口仍可能因缺参初读失败而被拒绝。该精确订阅契约的调整需单独设计初值返回值、诊断和兼容方式，本阶段保留现状；普通事件订阅和正则组合仍可接收其主动事件。

WS 精确分支复用此入口；WS regex 分支复用 SubscribeResources，因此业务实现无需增加 WS 专有列表判断或新观察状态协议。ACK 接受仍不表示全部匹配资源已开始观察。

## 5 常驻观察建立与所有权

EventHub 保存一组独立的常驻 ObservationHandle，由应用生命周期持有。

初始化先完成全部 AutoObserveList 正则匹配，再按资源路径去重；匹配超时发生时不会留下部分常驻批次。接着逐资源调用统一 AcquireResourceObservation。资源级 Skipped 和 Failed 记录诊断后继续处理其他资源。

常驻建立不创建 Token、不创建事件订阅，也不修改事件过滤器。已存在的观察比较基准沿用；新观察仍以有效初值为基准，不发布初值。轮询、变化判断、采样时间戳和事件发布继续使用 ResourceObservationManager。

初读失败不自动重试。后续显式建立一份新的普通订阅或独立观察需求，仍可以按照原有语义重新初读；这种重试不会补建之前失败的常驻需求。观察建立成功后的运行期读取失败仍由已有轮询机制在后续周期尝试。

## 6 释放和并发

- 本地退订、WS 退订或会话关闭只释放所属需求；列表句柄继续持有轮询。
- 未被列表选中的资源，最后一个按需句柄释放后停止。
- DisposeThings 在调用组件 Dispose 前停止全部观察并清理常驻句柄。
- EventHub.Dispose 和应用关闭走相同清理路径，重复释放幂等。
- 常驻句柄组在初读开始前已经归 EventHub 所有。关闭与初始化并发时，观察管理器禁止提交晚返回的初始化；句柄组也会拒绝并释放晚加入的句柄。
- 设备 getter 不在列表状态锁内执行。同步 getter 无法被强制中断；关闭后晚返回的结果不得再发布或留下观察引用。

## 7 诊断

`Hub.AutoObservationResults` 返回一次初始化的逐资源结果。资源可能为 Started、Shared、Skipped 或 Failed，包含路径、原因和必要的结构化原因码。它是建立时报告，不是持续健康状态，也不表示关闭后资源仍在运行。

报告不暴露常驻句柄，Handle 为 null；外部业务不能通过诊断结果释放应用拥有的常驻需求。初始化未完成时结果尚未公布；正常 StartThings 返回后可以读取完整报告。

未命中规则、资源跳过和初读失败记录 Warn。正则匹配异常会使列表初始化失败并清理本批次句柄；已存在的其他来源观察需求不会被本批次清理误释放。诊断复用本地日志，不扩展 WS 协议。

## 9 验收与验证

| 要求 | 验证点 |
|---|---|
| 旧配置兼容 | 缺省列表为空；原生数组和字典字符串往返一致；无效列表不部分应用 |
| 匹配一致 | 精确路径转义、完整正则、忽略大小写、重复规则去重、未命中与超时 |
| 黑名单优先 | 列表重叠、注册后 Start 前、精确、regex、独立句柄均不能绕过 |
| 事件仍有效 | 黑名单下本地和 WS 主动事件可收到，WS 完整与精简模式保留源端时间 |
| 常驻共享 | 没有事件订阅也读取；已有观察返回 Shared；退订和会话清理不释放常驻需求 |
| 参数和类型限制 | 必填参数不自动初读；默认参数可读取；原生事件、复杂类型、Method 不轮询 |
| 失败语义 | 初读失败可诊断、不自动重试、不阻断其他资源；正则匹配失败不放行 |
| 生命周期 | 初始化位于 Start 后；初始化幂等；关闭先于设备 Dispose；关闭中初读返回不遗留句柄 |
| 配置生效 | 运行中修改不改变快照；重建 Core 后读取新配置；外部数组变更不影响快照 |

## 2026-10-12 参数化订阅更新

最新使用规则见 [订阅使用设计文档](../订阅使用/订阅使用设计文档.md)。观察获取入口通过 ResourceInfo.HasGetterParameters 跳过所有含参数 getter，AutoObserveList 的 Default 测试由 Started 改为 Skipped，且不执行 getter。前文对应旧阶段的测试数量与精确初读限制保留为历史记录。
